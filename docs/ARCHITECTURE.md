# 多仓库架构约定

状态：2026-10-24 的组织约束已用于五个独立插件；截至 2026-10-29，五插件候选均已合并各自 `main`，作为个人实机测试开发基线。具体隔离验收与未验证边界见[五插件兼容记录](FIVE_PLUGIN_COMPATIBILITY.md)。

## 仓库边界

独立安装、升级、卸载的插件原则上独立仓库、版本、测试与发布。内部总是一起升级的功能不再拆仓。主仓库只维护产品文档、插件登记、兼容组合和集成验收；插件源码各自在独立仓库维护。

本约定替代 `AMADEUS_SPEC.md` v0.2 第 5 / 12 节中关于首版单仓库与 `packages/` 的建议布局，其余行为要求和需求 ID 不变。原规格保留为需求基线快照，不静默改写原文。

## 基础契约

身份、权限、Persona 与运行兼容属于基础责任。`amadeus-persona` 已作为独立 Host 插件实现一个选定 Workspace 的核心人格、可复用场景风格和可信 Session / QQ Scene 绑定。它通过两个独立的 DSH System Prompt Section 注入，不替换 Agent Preset、工具或执行期权限。跨 Scene 身份由 QQ Host 的稳定映射校验，不凭 Session 标题推断。无需为了这些接口另建 `amadeus-sdk`。

插件应声明能力、必要与可选依赖、接口兼容版本、健康状态、生命周期和降级行为。Manifest 不等于沙箱；可信身份、数据范围与外发权限必须实际执行检查。

## 调用与状态归属

- DSH 是唯一主推理与工具运行基础。
- Persona 管理稳定身份和场景表达，选定 Workspace 共享一份核心人格；QQ 群、私聊及普通 Session 可以覆盖风格。其他 Workspace 不受影响，子 Agent 默认不继承社交人格。Persona 不拥有记忆、状态、活动调度或外发能力。
- QQ 插件是 QQ 收发、等待、路由、去重与回执的唯一有效拥有者；Life 通过事件、唤醒或排队接口协作，不争抢消息游标。
- Life 管理注意力、未来意图和新增自主活动调度；没有 Life 时合法 QQ 连续对话仍独立运行。
- State 是状态唯一写入者，提供获授权的倾向；Memory 管理授权经历与召回，不接管任务执行。
- 身体提供器拥有自己的活动与资源租约；结果绑定原始活动、场景和数据范围。
- Persona 统一定义，场景历史与授权分别隔离。Memory 的记忆 ACL 与 QQ 的 Scene Guard 才是数据读取和平台执行权限；Persona 文本不能扩大这些权限。跨场景记忆允许最终一致，不能复制全量私聊历史。

## 版本与集成

通过明确版本与 main SHA 记录兼容组合，不依赖浮动 latest 或插件加载顺序。当前五插件组合见[版本清单](../compatibility/versions.yaml)与[五插件兼容记录](FIVE_PLUGIN_COMPATIBILITY.md)。这些记录说明已测的隔离 DSH Desktop 组合，不是生产依赖锁文件；正式 Release、npm 和 DSH Market 发布尚未执行。

仓库分开不能替代运行时解耦。必须验证禁用、移除、超时、权限故障、存储故障与恢复。身份或授权无法确认时，受影响动作不得默认放行。
